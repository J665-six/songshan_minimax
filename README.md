# MiniMax-H3 算子优化工程（单卡阶段）

> 目标：在初赛单卡（Hygon DCU BW，64 GB）上完成 MiniMax-H3 关键算子的
> **九齿实现 + 正确性验证 + 性能测量**，产出技术报告换取 8 卡资源。

---

## 一、单卡阶段验收标准

单卡阶段"做完"必须**同时**满足以下五组条件，缺一条都不算完成。

### A. 合规性（不满足即无效）

| # | 条款 | 判定方式 |
|---|---|---|
| A1 | 优化算子由 NineToothed 生成目标代码 | 能展示生成的 kernel 源码 / IR，且构建日志里有九齿调用 |
| A2 | 正式路径不 fallback 到 PyTorch / ATen | 用 `infinicore` 的算子调用，不走 `torch.*` |
| A3 | 未修改模型计算语义（不改公式、不降精度） | 与参考实现逐元素比对 |
| A4 | 未使用 Triton / CUDA 手写 kernel 绕开九齿 | 代码审查可追溯 |

### B. 正确性（硬阈值）

| 数据类型 | 判据 |
|---|---|
| bf16 | `rtol ≤ 1e-2` 且 `atol ≤ 1e-2`；余弦相似度 `≥ 0.999` |
| fp16 | `rtol ≤ 1e-2` 且 `atol ≤ 1e-2` |
| fp32 | `rtol ≤ 1e-5` 且 `atol ≤ 1e-5` |

- shape 覆盖必须包括 **H3 实际使用的形状**（见 `bench/cases.py`），不能只测玩具尺寸
- 边界：非连续输入、非 2 的幂长度、单 token、大 token 各至少 1 例

### C. 性能（可量化）

| 指标 | 门槛 |
|---|---|
| 单算子加速比 | 相对 InfiniCore 现有实现 **≥ 1.20×**（中位数） |
| 重复性 | 连续 3 轮测量的波动 **< 5%** |
| 资源 | 显存峰值不高于基线 +10% |

> 不设"端到端加速"作为单卡门槛——单卡装不下 33B DiT，端到端在 8 卡阶段测。

### D. 工程可复现

| # | 条款 |
|---|---|
| D1 | 一条命令完成：构建 → 正确性 → 性能 → 出 JSON |
| D2 | 结果文件包含：commit、DTK 版本、shape、耗时、误差、加速比 |
| D3 | 在干净目录里重跑能得到同样结论 |
| D4 | 改动以 patch 形式可 diff，原始文件留 `.orig` 备份 |

### E. 交付物

- 技术报告，必须覆盖赛题第 11 条要求的五项：
  1. 队伍信息
  2. 被优化算子及基线环境
  3. 优化思路
  4. 性能与正确性对比
  5. 代码位置和复现方式
- 发送至 `duhang@qiyuanlab.com`
- **报告被接受 = 拿到 8 卡账号 = 初赛阶段通关**

## 二、执行顺序

```
① 基准测量（摸清每个算子的真实性能）
      ↓
② 选目标（挑出加速空间最大、且九齿能覆盖的）
      ↓
③ 写九齿 kernel + 单测
      ↓
④ 复测 + 出对比数据
      ↓
⑤ 写报告 + 提交
```

**不做没有测量支撑的优化。**
