## 4. 模型实际运行顺序

### 4.1 整体 FL2VA 顺序

```text
输入 Resize
-> Qwen3-VL 文本/图像条件编码
-> 首帧视频 VAE encode
-> patchify + packed layout + initial noise
-> 49 × [
     DiT 50 blocks
     -> video scheduler step
     -> audio scheduler step
   ]
-> 移除 text/keyframe 条件行并 unpack
-> 视频 VAE decode
-> 音频 VAE decode
-> MP4 libx264/yuv420p/24fps 封装
```

默认 `scheduler.set_timesteps(50)` 得到 50 个 sigma 网格点。终点 sigma 不执行
DiT，因此实际 DiT forward 为 **49 次**，不是 50 次。

### 4.2 packed token 顺序

```text
[text tokens | keyframe tokens | target audio tokens | target video tokens]
```

默认 124 帧、768×1344 时，视频 latent frame 对应
`(H/32) × (W/32)` 个 token，整个 packed 序列约 **39,216 token**。

### 4.3 单个 DiT block 顺序

```text
AdaLN projection
-> token gather / six slices
-> RMSNorm1
-> (1 + scale_msa) * x + shift_msa
-> fused QKV
-> Q RMSNorm + K RMSNorm
-> one mRoPE(q, k)
-> non-causal self-attention
-> output projection
-> gated residual
-> RMSNorm2
-> (1 + scale_mlp) * x + shift_mlp
-> fused gate/up projection
-> SwiGLU
-> down projection
-> gated residual
```

主 block 每层包含：

- 5 个高层 Linear；
- 4 个 RMSNorm；
- 1 个 MHA；
- 1 个 mRoPE。

`context_embedder` 和 2 层 `token_refiner` 仅依赖固定 prompt，不应在 49 个
去噪步中重复执行。

### 4.4 视频 VAE 与音频 VAE

```text
视频编码：关键帧 -> causal spatial pad -> Conv3d stack -> GroupNorm/attention
视频解码：latent -> unpack -> ViT decoder -> causal Conv3d stack -> frames

音频编码：waveform -> weight-norm Conv1d stack -> Snake -> attention posterior
音频解码：latent -> dec_in_proj -> transposed-conv upsample
          -> anti-aliased SnakeBeta activation
          -> AMP residual blocks -> output Conv1d -> waveform
```

anti-aliased activation 的典型顺序是：

```text
ConvTranspose1d upsample -> SnakeBeta -> Conv1d downsample
```

这是 NineToothed SnakeBeta 和 weight-norm 物化能够直接作用于实际 VAE 路径的
原因。

### 6.1 DiT 正式路径

| 算子 | 优化前 | 优化后 | 路径状态 | 性能改变 | 正确性 |
|---|---|---|---|---|---|
| Hygon non-causal MHA | `QK^T -> softmax -> AV`，物化 `56×S×S` | `at::scaled_dot_product_attention`，非因果 | 正式 C++ 路径 | 3.730×@1024；7.811×@4096 | cosine 0.999980–0.999996 |
| MHA 构建条件 | 仅 `ENABLE_FLASH_ATTN` 可注册 | `ENABLE_ATEN` 构建也可注册 | 正式后端 | 解决无 flash-attn ABI 时的路由 | 已运行验证 |
| AdaLN affine | `scaled=x*scale; y=(x+scaled)+shift` | `addcmul(x,x,scale,1)+shift` | 正式 C++ 路径 | 1.317–1.320× | cosine 0.999997 |
| gated residual | `mul + add` | 单次 `addcmul` | 正式 C++ 路径 | 1.601–1.614× | cosine 0.999997，参考 `max_abs=0` |
| Q/K RMSNorm | 固定按设备最大线程启动 | `dim<=128/256/512` 使用 128/256/512 threads | 正式 C++ 路径 | 仅测当前延迟，未做同进程旧/新 A/B | cosine 0.99999994–1.00000024 |
| mRoPE | 每行最多 256 threads | 按有效 rotary width 对齐；H3 为 64 threads | 正式 C++ 路径 | 仅测当前延迟，未做旧/新 A/B | Q/K cosine 1.0，`max_abs=0` |

### 6.4 NineToothed SnakeBeta JIT

优化前是 PyTorch 的多次逐元素表达：

```text
exp(alpha)
exp(beta)
sin(...)
square
divide
add
```

NineToothed 版本：

```text
参数加载时：alpha_exp=exp(alpha_log), beta_exp=exp(beta_log)
每次 forward：一个 fused kernel 计算 x + sin(alpha_exp*x)^2/(beta_exp+1e-9)
```

固定 `1×512` tile、4 warps，动态覆盖任意音频长度：

| shape `[B,C,L]` | PyTorch | NineToothed JIT | 加速 | 正确性 |
|---|---:|---:|---:|---|
| `[1,128,207]` | 0.0756 ms | 0.0489 ms | 1.547× | cosine 1.0，`max_abs=0` |
| `[1,128,2048]` | 0.0761 ms | 0.0544 ms | 1.398× | cosine 1.0，`max_abs=0` |
| `[1,128,16384]` | 0.1198 ms | 0.0498 ms | 2.404× | cosine 0.99999994，`max_abs=0` |
| `[1,128,331200]` | 2.0219 ms | 0.8601 ms | 2.351× | cosine 0.99999988，`max_abs=0` |

正式模块：

```text
InfiniCore/src/infiniop/ops/snake_beta/ninetoothed/snake_beta.py
InfiniCore/python/infinicore/nn/functional/snake_beta_ninetoothed.py
```

VAE 接线：

```text
InfiniLM/python/infinilm/multimodal/audio_kernels.py
install_ninetoothed_audio_kernels(pipe.audio_vae)
```

集成测试：

- `B=2,C=64,L=207/331200`：cosine 1.0，`max_abs=1.907e-06`；
- 只替换 forward，不改变 state dict；
- 安装幂等；
- 训练模式自动回退原始 PyTorch forward。

### 6.5 SnakeBeta Hygon AOT

| 16384 | 0.1192 ms | 0.1063 ms | 1.121× | cosine 1.0，`max_abs=0` |

AOT 满足可生成、可加载、可执行和数值正确。动态 JIT 在短长度更快，因此正式
forward 默认使用 JIT；AOT 产物保留用于比赛审计和部署验证。

### 6.6 Audio weight-norm

| 项目 | 优化前 | 优化后 |
|---|---|---|
| weight 表示 | state dict 保存 `weight_g/weight_v` | 推理前物化为普通 `weight` |
| 每步计算 | 每次 Conv forward 重新归一化 | 只物化一次 |
| hook | forward 前 hook 持续存在 | 移除 hook |
| 公式 | `weight = g * v / ||v||` | 物化结果完全等价 |
| checkpoint | 原权重不训练、不量化 | 仅转换推理表示 |

结果：

- Conv1d：0.1506 ms -> 0.1136 ms，1.326×；
- ConvTranspose1d 输出同样 `max_abs=0`；
- `weight_g` 剩余数量为 0；
- 重复运行范围约 1.326×–1.418×。

### 6.7 NineToothed RMSNorm / Add-RMSNorm 消融（2026-11-01 补录）

这一组与 §6.1 的“Q/K RMSNorm launch 调整”是**两件不同的事**：

- §6.1 改的是**启动参数**（线程数），不减少访存；
- 本节改的是**访存结构**（把两次读改为一次读），是真正的算子重写。

统一消融 harness：`tasks/ablation_run.py`。控制变量如下：

| 计时 | 10 次预热 + 50 次迭代 + 前后 synchronize，3 轮取中位 |
| 参考 | 同一个 PyTorch fp32 实现 |
| **唯一变量** | **InfiniCore 基线 vs NineToothed** |

**RMSNorm**

|---|---:|---:|---:|---:|---:|

### 6.8 NineToothed 效率分区规律（新增）

为解释 §9 中多个负收益案例，做了输入数对照探针（`kernels/nt_efficiency_probe.py`）：

| 输入数 | 九齿带宽 | 占峰值 | torch 带宽 | 占峰值 |
|---|---:|---:|---:|---:|
| 1（纯拷贝） | 304 GB/s | **23%** | 1307 GB/s | 97% |
| 2 | 313 GB/s | 23% | 1310 GB/s | 97% |
| 3 | 306 GB/s | 23% | 880 GB/s | 65% |
| 4 | 302 GB/s | 22% | 732 GB/s | 54% |

**九齿在纯元素级场景下，与输入个数无关，稳定在峰值的 22–23%。**

而带行归约的算子：

| 算子 | 九齿带宽 | 占峰值 |
|---|---:|---:|
| RMSNorm | 852–1152 GB/s | 64–86% |
| Add-RMSNorm | 1113–1159 GB/s | 83–87% |

**结论（对选型有决定性意义）**：

```text
带行归约  →  九齿可用（64–87% 峰值）
纯元素级  →  九齿不可用（22–23% 峰值），应改走 addcmul / torch 串联
```

这条规律解释了：为什么 SnakeBeta（带 pow/exp/sin 的规约式长向量）能到 1.4–2.4×，
而 SiLU-and-Mul、AdaLN 融合全部失败。
