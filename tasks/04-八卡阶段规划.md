# 三、八卡阶段运行与开发规划

## 3.1 目标

在 8 卡资源上完成完整 FL2VA 生成，并把单卡阶段已验证的算子优化在端到端链路上兑现。

| 优先级 | 目标 | 验收标准 |
|---|---|---|
| P0 | 完整 FL2VA 跑通 | 输出 MP4 的帧数、分辨率、帧率、编码、音频规格全部符合媒体契约 |
| P0 | 端到端可测量 | 分段耗时与峰值显存落盘，3 次取中位 |
| P1 | 候选算子接线 | RMSNorm 与 Add-RMSNorm 进入正式分发，cosine ≥ 0.9999 |
| P1 | 相对基线加速 | 同配置端到端加速比 > 1.0，且 SSIM 不低于基线 |
| P2 | VAE 段优化 | native 版本超过 PyTorch 才接入，否则保留原路径 |
| P3 | 可复现 | 干净环境按文档重建并跑通 |

## 3.2 卡时预算

单卡阶段剩余约 95 卡时，按 8 卡计约 11.9 小时墙钟。

| 阶段 | 卡时 | 内容 |
|---|---:|---|
| P0 环境与首次跑通 | 6 | 权重校验、8 卡启动、单次生成 |
| P1 端到端基线 | 10 | 3 次生成、SSIM 标定、分段耗时 |
| P2 候选算子接线 | 14 | RMSNorm / Add-RMSNorm 接入与回归 |
| P3 多卡切分与调优 | 26 | TP 切分、显存分阶段、通信重叠 |
| P4 VAE 段优化 | 14 | GroupNorm / Conv1d / ConvTranspose1d |
| P5 复现与交付 | 10 | 干净环境重建、打包 |
| 缓冲 | 15 | 工具链与通信返工 |
| **合计** | **95** | |

## 3.3 里程碑

| 里程碑 | 内容 | 卡时上限 |
|---|---|---:|
| M1 | 8 卡首次生成出合规 MP4 | 6 |
| M2 | 端到端基线与 SSIM 落盘 | 16 |
| M3 | 候选算子进入正式路径 | 30 |
| M4 | 端到端加速比 > 1 | 56 |
| M5 | VAE 段优化或明确不采用 | 70 |
| M6 | 干净环境复现与打包 | 80 |

**顺序约束**：M3 之前不做 VAE 迁移，先确保主链有可交付结果。

## 3.4 工作项

1. **环境与权重就绪**：下载并校验约 135 GB 权重，建立 8 卡启动脚本，确认 RCCL 通信正常。
2. **完整 FL2VA 首次跑通**：以官方默认参数（50 步、124 帧、768×1344、seed 42）生成首个合规视频，VAE 保持 PyTorch 路径。
3. **端到端基线标定**：连续 3 次生成取中位，按 `minimax_h3_compare.py` 口径计算 SSIM，记录各阶段占比。
4. **候选算子接线**：把 NineToothed RMSNorm（2.04×）与 Add-RMSNorm（1.80×）迁入 `src/infiniop/ops/<op>/ninetoothed/` 并在 `operator.cc` 注册 HYGON 分发；单算子回归通过后再替换 DiT 调用点，每替换一处做一次端到端 SSIM 校验。
5. **多卡切分与调度**：先做 TP 切分容纳完整 DiT；利用 AdaLN 只依赖 `(timestep, modality)` 的特性预计算调制表并卸载对应权重；分阶段加载条件编码器、DiT、VAE；通信与计算重叠。
6. **VAE 段优化**：用 NineToothed 重写 GroupNorm 等热点，沿用单卡阶段验证过的行归约写法（DCU 上可达 83–87% 峰值带宽）；若不及 PyTorch 则不接入。
7. **稳定性与复现**：连续 3 次生成检查波动与显存，在干净目录重建验证。

## 3.5 复现要求

- 一条命令跑通：`scripts/run_fl2va_8gpu.sh`，参数外置，默认即官方配置
- 每次运行输出 MP4、分段耗时 JSON、峰值显存、SSIM
- 记录三个仓库 commit、DTK、torch、Triton、NineToothed 版本
- 每个作业保留 Slurm JobID，可用 `sacct` 复核卡时
- 每项优化单独提交并附前后对比，不做捆绑式提速声明

## 3.6 完成信心

八卡阶段的工作是把单卡阶段已验证的组件在完整模型上组合与调优，而非探索未知：工具链已打通，AOT 已可用，VAE 接口已补齐并通过官方测试，端到端计时口径已固化。预算中预留了 15 卡时（约 16%）缓冲，各里程碑设有卡时上限，任一环节超支都可回退到上一个稳定状态交付。
