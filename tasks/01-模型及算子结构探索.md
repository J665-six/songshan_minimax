## 一、模型全景

MiniMax-H3 是一个**联合生成视频与音频**的扩散模型。赛题只要求 FL2VA（首帧 + 文本 → 视频）。

```
                    ┌─────────────────────────────────────────────┐
   首帧图像 ────────►│  视频 VAE 编码器（Causal Conv3d + ResNet）    │──► 首帧 latent
                    └─────────────────────────────────────────────┘

                    ┌─────────────────────────────────────────────┐
   文本提示词 ──────►│  Qwen3-VL 32B（取第 50 层隐状态，不跑 lm_head）│──► 文本条件向量
                    └─────────────────────────────────────────────┘

                                    ▼
                    ┌─────────────────────────────────────────────┐
                    │  DiT Transformer（50 层，hidden=5376）        │
                    │  音频 + 视频 token 打包在一条序列里            │
                    │  迭代去噪 × N 步                              │
                    └─────────────────────────────────────────────┘
                                    │
                 ┌──────────────────┴──────────────────┐
                 ▼                                     ▼
    ┌────────────────────────┐          ┌────────────────────────┐
    │ 视频 VAE 解码器（ViT）  │          │ 音频 VAE 解码器（DAC）  │
    │ 36 层 Transformer       │          │ ConvTranspose1d + Snake│
    └────────────────────────┘          └────────────────────────┘
                 │                                     │
                 ▼                                     ▼
              视频帧                                音频波形
                 └──────────────┬──────────────────────┘
                                ▼
                          封装为 mp4
```

## 二、各组件详解

### 2.1 组件清单（来自 `model_index.json`）

| 组件键 | 类 | 参数量级 | 权重体积 | 作用 |
|---|---|---|---|---|
| `text_encoder` | `Qwen3VLForConditionalGeneration` | 32B | **63 GB** | 文本/图像条件编码 |
| `tokenizer` | `Qwen2TokenizerFast` | — | 11 MB | 分词 |
| `processor` | `Qwen3VLProcessor` | — | 11 MB | 图像预处理 |
| `transformer` | `MiniMaxH3Transformer3DModel` | 33B | **62 GB** | DiT，去噪主干 |
| `transformer_ref` | 同上 | 33B | （Ref2VA 用） | 本赛题不用 |
| `vae` | `AutoencoderKLMiniMaxH3` | ~1.8B（解码器）+ 编码器 | 9.8 GB | 视频 latent ↔ 像素 |
| `audio_vae` | `AutoencoderKLMiniMaxH3Audio` | ~0.2B | 578 MB | 音频 latent ↔ 波形 |
| `scheduler` | `MiniMaxH3Scheduler` | 无参数 | — | 视频去噪调度 |
| `audio_scheduler` | `MiniMaxH3Scheduler` | 无参数 | — | 音频去噪调度 |

> FL2VA 子目录合计 **135 GB**（实测下载体积）。

### 2.2 DiT 主干：`MiniMaxH3Transformer3DModel`

关键超参（`transformer/config.json`）：

| 参数 | 值 | 含义 |
|---|---|---|
| `num_attention_heads` | 56 | 注意力头数 |
| `attention_head_dim` | 128 | 每头维度 |
| `hidden_size` | **5376** | = 56 × 128 |
| `num_layers` | **50** | 主干层数 |
| `num_refiner_layers` | 2 | 文本 token 精炼层 |
| `ffn_dim` | 14336 | FFN 中间维度 |
| `in_channels` | 24 | 视频 latent 通道 |
| `audio_in_channels` | 32 | 音频 latent 通道 |
| `patch_size` | [1, 2, 2] | 时空 patch |
| `text_dim` | 5120 | 文本条件维度 |
| `freq_dim` | 256 | 时间步编码维度 |
| `time_embed_hidden_dim` | 5376 | 时间嵌入隐层 |
| `time_embed_dim` | 2688 | AdaLN 调制向量维度 |
| `rope_freq_dim` | 16 | RoPE 频率维 |
| `rope_theta` | 10000.0 | RoPE 基频 |

**结构要点**

1. **单文档打包**：音频 token、视频 token、文本 token 拼在**一条序列**里，用
   `token_tags` 标记类型（0=视频，1=文本，2=音频），用 `video_indices` / `audio_indices` /
   `text_indices` 记录各自在序列中的位置。全文没有 cross-attention（源码注释明确写了
   `There is no cross-attention anywhere in MiniMax-H3`）。

2. **多时间步共存**：一条序列里可以同时存在**不同的噪声水平**——目标视频、目标音频、
   条件行各有各的 timestep。`timestep` 参数传的是"去重后的时间步列表"，
   `timestep_indices` 记录每行对应哪一个。一次前向即可服务多个噪声水平。

3. **AdaLN 调制**：`adaln_indices = timestep_indices × 3 + token_tags`，
   每个 block 据此从调制表里取 `shift/scale/gate`，对隐状态做 affine。

4. **门控残差**：注意力输出和 FFN 输出分别乘 `gate_msa` / `gate_mlp` 再加回残差。

5. **Tokenizer refiner**：文本 token 先过 2 层无 AdaLN、无 RoPE 的标准 block。

6. **混合精度（重要）**：
   `proj_in`、`audio_proj_in`、`time_embedder`、两个输出头都在 **float32**，
   `context_embedder` 和 block 堆栈在 **bfloat16**。源码里 `_keep_in_fp32_modules`
   显式控制这份名单。**移植时不能一刀切改成 bf16，否则输出会偏。**

### 2.3 单个 DiT Block 的数据流

源码（`MiniMaxH3TransformerBlock.forward`）逐行对应：

```
hidden_states ─┬─────────────────────────────────────────────► (+) ──┐
               │                                                      │
               ├─► RMSNorm(norm1) ──► ×(1+scale_msa) + shift_msa ─┐   │
               │                                                   │   │
               │                          ┌────────────────────────┘   │
               │                          ▼                            │
               │                    Attention                          │
               │                          │                            │
               │                    × gate_msa                        │
               ▼                          ▼                            │
            残差 ──────────────────────► (+) ◄─────────────────────────┘
                                          │
                                          ├──────────────────────────► (+) ──► 输出
                                          │                              ▲
                                          ├─► RMSNorm(norm2) ──┐        │
                                          │   ×(1+scale_mlp)+shift_mlp    │
                                          │         ▼                    │
                                          │    FeedForward(SwiGLU)       │
                                          │         ▼                    │
                                          │     × gate_mlp ──────────────┘
```

### 2.4 Attention 内部（`MiniMaxH3AttnProcessor`）

```
x ──► Linear(to_q) ──► reshape(56, 128) ──► RMSNorm(dim_head) ──► RoPE ──┐
  ├─► Linear(to_k) ──► reshape(56, 128) ──► RMSNorm(dim_head) ──► RoPE ──┤
  └─► Linear(to_v) ──► reshape(56, 128) ──────────────────────────────────┤
                                                                          ▼
                                                        Scaled Dot-Product Attention
                                                                          │
                                                        ┌─────────────────┘
                                                        ▼
                                              flatten ──► Linear(to_out)
```

**注意**：`norm_q` / `norm_k` 是**逐头 RMSNorm**（在 head_dim=128 维度上归一化），
这与主干里的 `norm1/norm2`（在 hidden=5376 上归一化）是**不同的 shape**，
优化时需要分别处理。

### 2.5 视频 VAE

**编码器**：Causal 3D 卷积堆叠

```
6 级 block × (Causal Conv3d + GroupNorm + ResNet×2) + 时空下采样
通道数：[128, 256, 256, 512, 512, 1024]
空间下采样因子：[2,2,2,2,1,1]  → 合计 16×
时间下采样因子：[1,2,2,1,1,1]  → 合计 4×
norm_num_groups = 32, eps = 1e-6, padding = reflect
```

**解码器**：**不是卷积，是 36 层 ViT**

| 参数 | 值 |
|---|---|
| 层数 | 36 |
| dim | 2048（32 头 × 64） |
| FFN 倍数 | 4（SwiGLU） |
| register tokens | 4 |
| RoPE | 3 轴（t/h/w），theta=100，rope_dim_ratio=0.75 |
| patch 输出 | 每 token 展开成 4×16×16 像素块 |
| 分块 | 默认开启，256×256 瓦片，重叠 64 |

解码器估算参数量 ≈ **1.8B**（约 3.6 GB bf16）。

**关键精度约束**（源码注释明确要求）：
`norm_q`、`norm_k`、`norm1`、`norm2`、`norm_out` 全部在 **float32** 下计算，
再转回 bf16。这是精度红线。

### 2.6 音频 VAE

BigVGAN / DAC 风格：

```
latent(32ch) ──► Conv1d ──► 上采样链(×5,×5,×2,×2,×2,×2,×2) ──► Conv1d ──► 波形(32kHz)
                  每级：ConvTranspose1d + 3×(dilated Conv1d + Snake 激活)
                  注意力块：Causal Attention + GEGLU MLP
```

| 参数 | 值 |
|---|---|
| encoder_dim | 64 |
| latent_dim | 2048 |
| decoder_dim | 1024 |
| decoder_kernel_sizes | [9,9,4,4,4,4,4] |
| resblock_kernel_sizes | [3,7,11] |
| dilation | [1,3,5] |
| 采样率 | 32 kHz |

## 三、推理时的数据工作流

### 3.1 单次 FL2VA 调用（官方入口 `examples/minimax_h3.py --task fl2va`）

```
① 加载阶段
   ├─ 加载 modular pipeline（diffusers）
   ├─ 加载 text_encoder（63 GB）
   ├─ 加载 transformer（62 GB）
   └─ 加载 vae + audio_vae（10.4 GB）

② 条件编码
   ├─ 图像：processor 预处理 → 缩放到目标分辨率 → 像素张量 [1,3,1,H,W]
   │        → 视频 VAE 编码器 → 首帧 latent [1,24,1,H/16,W/16]
   ├─ 文本：tokenizer → input_ids + Qwen3-VL 图像特征
   │        → Qwen3-VL 前 50 层 → 文本条件 [1,L,5120]
   │        → token refiner（2 层）→ [1,L,5376]
   └─ 音频：参考音频（可选）→ audio_vae 编码器 → 音频 latent

③ 初始化
   ├─ 随机噪声 latent（视频：124 帧 → 31 个时间步）
   ├─ 首帧 latent 写入第 0 帧（首帧约束）
   └─ 构造 position_ids（3 轴：t/h/w）+ token_tags

④ 去噪循环 × 50 步（默认 steps=50）
   for t in scheduler.timesteps:
       ├─ timestep embedding（sinusoidal → MLP）
       ├─ AdaLN 调制表预计算（每步按 timestep/modality 查表）
       ├─ DiT 前向：50 层 × TransformerBlock
       │     每层 = RMSNorm + AdaLN调制 + Attention + 门控残差
       │            + RMSNorm + AdaLN调制 + SwiGLU FFN + 门控残差
       ├─ 分离视频/音频预测
       └─ scheduler.step() 更新 latent

⑤ 解码
   ├─ 视频 VAE 解码：latent [1,24,31,H/16,W/16]
   │      → 36 层 ViT（分块处理）
   │      → 像素 [1,3,124,H,W]
   ├─ 音频 VAE 解码：音频 latent → 波形
   └─ 封装：图像序列 + 音频 → mp4（ffmpeg）

⑥ 输出
   └─ mp4 文件（124 帧 @ 24fps ≈ 5.17 秒）
```

### 3.2 显存/时间分布（估算）

序列长度计算（720p / 124 帧）：

```
latent 帧数 = 124 / 4 = 31
latent 高   = 720 / 16 = 45
latent 宽   = 1280 / 16 = 80
视频 token  = 31 × 45 × 80 = 111,600
```

| 阶段 | 占比（估） | 依据 |
|---|---|---|
| DiT 去噪 50 步 | **~85%** | 33B × 50 次前向 |
| 视频 VAE 解码 | ~10% | 36 层 ViT，11 万 token（分块后） |
| 文本编码 | ~4% | 32B 单次前向 |
| 首帧编码 + 封装 | ~1% | — |

## 五、探索中确认的关键事实

1. **没有 cross-attention**：文本条件通过 `encoder_hidden_states` 拼接进打包序列，
   与音视频 token 一起做 self-attention。这简化了优化面——只需优化一种 attention。

2. **AdaLN 占了 39% 的参数**：约 13B / 33B 的参数在 AdaLN 分支上，但它的输出只依赖
   `(timestep, modality)`，与序列长度无关，**可以在去噪前预计算整张表**。
   这是一个巨大的优化机会：预计算后这部分权重可以从显存卸载。

3. **音频与视频共享同一个 DiT**：不是两个模型，是一条序列里的两种 token。
   所以"音频处理"不等于"多一个模型"。

4. **VAE 解码器是 ViT 不是卷积**：36 层、dim 2048、全注意力、3 轴 RoPE。
   这意味着 VAE 迁移的工作量比想象中大——它本质上是第二个 Transformer。

5. **文本编码器只用前 50 层**：Qwen3-VL 32B 有更多层，H3 只取第 50 层隐状态，
   且跳过 final norm 和 lm_head。下载的 63 GB 权重里有相当一部分用不上。

## 六、对后续优化的启示

| 观察 | 优化机会 | 预期收益 |
|---|---|---|
| AdaLN 输出只依赖 (t, modality) | 去噪前预计算调制表，卸载 AdaLN 权重 | 显存 -13B 参数（~26 GB bf16） |
| 无 cross-attention | 只需优化 self-attention 一种形态 | 减少实现工作量 |
| VAE 解码器是 36 层 ViT | 与 DiT 共用 attention/norm 算子实现 | 算子复用 |
| RMSNorm 调用 172 次/前向 | 重写为高带宽实现 | **已实现 2.0–2.5×** |
| Add-RMSNorm 每层一次 | 融合实现 | **已实现 1.55–1.84×** |
| 文本编码器只取前 50 层 | 只加载需要的层 | 权重加载时间 -30% |
