# Add-RMSNorm 融合算子优化结果（单卡 · Hygon DCU BW）

实测时间：2026-10-28 04:00
环境：DTK 26.04 / torch 2.5.1 HIP 6.3.25405 / 峰值拷贝带宽 1342 GB/s

## 一、动机

H3 的每个 DiT block 和 VAE decoder block 都是这个模式：

```
residual = residual + x
y        = rms_norm(residual, w)
```

InfiniCore 已有融合的 `add_rms_norm`，但只跑到 **605 GB/s（峰值的 45%）**。
这里用 rms_norm 已验证有效的行归约模式重写：一次读入、两次写出（归一化结果 + 残差），
不再有中间张量往返。

## 五、为什么它比 SiLU 成功

同一个工具、同样的写法，结果完全相反，原因在**访存模式**：

| | RMSNorm 系 | SiLU-and-Mul |
|---|---|---|
| 每个 program 处理 | 一整个行（5376 元素） | 一小段流式数据 |
| 索引算术 | 摊薄在 5376 个元素上 | 每个元素都要算一次 |
| 生成代码的 mask 开销 | 可忽略 | 淹没真实访存 |
| 实测带宽 | 1107–1184 GB/s | 457 GB/s |

结论：**九齿当前版本的代码生成对"行式"算子友好，对"长流式"算子不友好。**

## 六、结论

- 达到验收标准：**加速比 1.55–1.84×**，cos ≥ 0.9999，波动 0.08%
- 与 rms_norm 一起，构成两个可交付的算子结果
- 两者都是 H3 主链路上的高频算子：
  - RMSNorm：DiT 50 层 × 2 + VAE 36 层 × 2 = **172 次/前向**
  - Add-RMSNorm：每个 block 的残差分支，同样量级
